# NEXT_UPGRADE_PLAN

按优先级排序。每项都标注了验收标准，避免"做了但无法验证"。

## P0 / P1（下一轮应优先）

### 1. 浏览器端到端测试
- **问题**：核心用户流程（创建房间 → 搜索 → 点歌 → 同步播放 → 聊天 → 房主管理）没有任何端到端证据。
- **做法**：引入 Playwright，跑在隔离端口与临时数据目录；覆盖桌面视口 + 移动视口。
- **验收**：CI 中稳定通过；失败时输出截图与 trace；不依赖真实外部音源（用本地 mock 服务）。

### 2. 媒体代理域名白名单
- **问题**：`/api/media-proxy` 仍可代理任意公网 URL（有 SSRF 拦截与 IP 限流，但仍是开放代理）。
- **做法**：按音源 CDN 后缀白名单 + 可配置额外域名；默认拒绝未知域。
- **验收**：未知域返回 403；四平台真实播放链路回归通过。

### 3. Redis 多实例一致性
- **问题**：本轮修复均为单实例内存语义；Redis 模式下房间生命周期与播放锁未验证。
- **做法**：起两个实例 + Redis，验证房间创建/销毁、并发切歌、广播去重。
- **验收**：两实例下房间状态一致；无重复广播；销毁后无残留 key。

## P2

### 4. `Room.tsx` 拆分
- 先补行为测试（队列操作、播放控制、权限分支），再按「搜索 / 队列 / 聊天 / 播放器」拆组件。
- 验收：拆分前后测试全绿，包体不增大。

### 5. 依赖与发布链
- 跑 `npm run audit:prod`（官方 registry）。
- Android release 签名 APK + Windows NSIS 安装包各做一次安装/升级/卸载回归。
- 验收：Release 资产可安装；升级保留 `server/data`。

### 6. 前端错误可观测性
- 增加全局 `error` / `unhandledrejection` 上报（可选、默认关闭、可配置端点）。
- 验收：错误带 `requestId` 与服务端日志可关联。

## P3

### 7. 可访问性复查
- 全站 `aria-live` 覆盖动态状态；键盘焦点顺序；对比度审计。
- 验收：键盘可完成创建/加入/点歌/发送聊天。

### 8. `knownUserIds` 字段清理
- 该字段当前无读取方，仅被序列化。评估后从快照中移除。
- 验收：旧数据可正常恢复；快照体积下降。

### 9. 房间列表轮询优化
- 当前 5 秒全量拉取；可改为条件请求/增量版本号。
- 验收：空变更时传输量下降 > 80%。

## 不建议做

- 插件系统、云端跨设备同步、全局搜索：当前核心路径的可靠性验证仍未补齐，功能扩张会放大维护成本。
- 直接移植 AGPL 项目代码：许可证不兼容。
